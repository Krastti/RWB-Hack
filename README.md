# RWB-Hack

Платформа подготовки исходников приложений по бизнес-требованиям. Пользователь
задаёт текст; целевой агентный конвейер формирует анализ, архитектуру, код и
документацию согласованного проекта. Парковочный помощник из конкурсного кейса —
пример входа, а не предметная область, зашитая в платформу.

## Документация

- [Backend платформы](docs/backend.md): API, конфигурация, PostgreSQL, сервисы и lifecycle.
- [Frontend платформы](docs/frontend.md): Angular, сессия, экраны, polling и разработка.
- [Агенты](docs/agents.md): C-02, LLM, анализ, LangGraph, профиль и ownership.
- [Участие в разработке](CONTRIBUTING.md) и [шаблон PR](.github/pull_request_template.md).

Единственные нормативные источники форматов: [HTTP OpenAPI](contracts/platform.openapi.yaml),
[agent schemas](contracts/agents/v1/), [Run lifecycle](contracts/lifecycle.md),
[профиль генерации](templates/profiles/web-fastapi-angular/profile.json) и
[схема профиля](templates/profiles/web-fastapi-angular/profile.schema.json).
Документация объясняет реализацию; примеры не заменяют эти контракты.

## Продукт и границы первой версии

Платформа и создаваемый ею проект — разные приложения с разными API, БД и
учётными данными. Стек платформы: Angular 22/TypeScript/Bootstrap 5.3/SCSS,
FastAPI/Pydantic/SQLAlchemy/PostgreSQL. Миграции платформы — Flyway SQL.
Первый профиль **генерируемого проекта** — `web-fastapi-angular` 1.0.0:
Angular/Bootstrap + FastAPI/PostgreSQL, миграции Alembic.

Первая продуктовая версия задумана для одного автора: собственные проекты,
неизменяемые ревизии требований, история запусков, ограниченные уточнения,
архитектура API/data/UI, генерация web-кода/миграций/документов, контроль расхода,
отмена, повтор, просмотр файлов, ZIP и экспорт снимка в настроенный GitLab.
Командное редактирование, произвольный браузерный редактор исходников и исполнение
сгенерированного кода внутри платформы в эту версию не входят. `completed` означает
«проект подготовлен», а не «собран, протестирован и развёрнут».

Обязательный предметный вход — только бизнес-требования. Существенные вопросы
касаются прав, безопасности, архитектуры и ключевых сценариев; остальные решения
оформляются отдельными допущениями. Стабильные `FR-001` связываются с критериями,
экранами, API, сущностями и файлами. Факты, допущения и вопросы не смешиваются.
Mock допускается только для явно обозначенных недоступных внешних систем, а не
для основной логики, прав или сохранения данных. Секреты не попадают в prompt,
артефакты и логи; модель не получает права выбирать инструменты или пути на сервере.

## Архитектура и фактическое состояние

Целевая цепочка: Angular → REST `/api/v1` → FastAPI/PostgreSQL → очередь/worker →
LangGraph → LLM adapter → артефакты/snapshot → ZIP/GitLab. Celery queue adapter и StageWorker существуют; им требуется предметный orchestrator; технический recovery встроен
callables и не образуют автоматически сквозной pipeline.

| Область | Что есть в коде | Ограничение интеграции |
|---|---|---|
| HTTP и БД | Factory, JWT, проекты/ревизии, PostgreSQL repositories, ORM Run/attempt/event/idempotency, Flyway V1–V9 | Штатная factory подключает auth/projects/createRun/Run GET/cancel/retry/answers; выдача требует отдельной интеграции |
| Run | Общий PostgreSQL runtime, createRun→attempt dispatcher, lifecycle, cancel/retry, queue/lease adapter, StageWorker | Worker factory требует предметный orchestrator, технический recovery встроен; C-02/artifact/LangGraph bridge и полный протокол восстановления ещё не подключены |
| Анализ | A-01 adapter, A-02 prompt/renderer, legacy analyst, A-04 граф с durable SQLite checkpoints | Legacy 0.1 не является узлом C-02; полный bridge аналитика/worker отсутствует |
| UI | Вход, проекты, Run monitor/timeline, вопросы, просмотр анализа, команды | Доступность экрана не подтверждает наличие соответствующего backend endpoint |
| Генерация и выдача | Schemas, профиль, связанные fixtures | Полные architecture/coding/assembly/storage/ZIP/GitLab runtime не интегрированы |

Связанные ограничения описаны в интеграционных задачах
[#127](https://github.com/Krastti/RWB-Hack/issues/127),
[#128](https://github.com/Krastti/RWB-Hack/issues/128),
[#129](https://github.com/Krastti/RWB-Hack/issues/129),
[#130](https://github.com/Krastti/RWB-Hack/issues/130),
[#131](https://github.com/Krastti/RWB-Hack/issues/131).
Состояние Issue само по себе не доказывает end-to-end готовность.

## Быстрый старт

Из корня репозитория, Python 3.11+; совместное окружение проверяется отдельно от
доступности PostgreSQL и LLM:

```sh
python -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-worker.txt
.venv/bin/python -m pip check
.venv/bin/python contracts/agents/validate.py --check
```

Для API нужны отдельная PostgreSQL, миграции, JWT-секрет и заранее созданный
пользователь: [инструкция backend](docs/backend.md#установка-и-запуск).
Для Angular нужен Node.js 24.15+ ветки 24.x:

```sh
cd frontend
npm ci
npm start
```

Открыть `http://localhost:4200`; `/api` проксируется на `127.0.0.1:8000`.
[Offline-примеры агентов](docs/agents.md#проверки-и-примеры) не вызывают платную модель.
Инструкции не являются подтверждением запуска БД, реального LLM или полного pipeline.

## Требования и план развития

Источники: [исходный кейс PDF](docs/Агентский_ИИ_пайплайн_полного_цикла_разработки_корпоративных.pdf)
(разделы 1–7 и приложение №1) и командные решения о web-профиле. В PDF указан
Angular/C#/Kotlin; FastAPI — решение команды на основании сообщённого разрешения
смены технологий, а не цитата из PDF. Mobile Kotlin/Compose, PostGIS и геосценарии —
отдельные расширения; Kafka нужна только при предметном обосновании.

| Требование платформы | Ожидаемый результат |
|---|---|
| PF-001–002 | Собственный проект с неизменяемым текстом; асинхронный Run с `202` |
| PF-003–004 | Этапы/события и критические вопросы текущей ревизии |
| PF-005–006 | Версионированные артефакты и трассировка всех FR, включая непокрытые |
| PF-007–008 | Безопасная отмена/повтор и остановка по бюджету с частичными результатами |
| PF-009–010 | ZIP/экспорт одного снимка и достоверные метрики/история |
| PF-011–012 | Изоляция владельцев и документированные внешние адаптеры |

Это требования, а не перечень реализованных функций. Цепочка зависимостей:
контракты C-01–C-05 → проекты B-01–B-04/F-01–F-05 → Run B-05–B-11/F-06–F-08 →
анализ A-01–A-04/B-12–B-13/F-09–F-10 → архитектура A-05–A-09 → генерация
A-10–A-18 → storage/assembly/выдача B-14–B-18/A-19/F-11–F-12 → общий учёт
B-19–B-21/A-20/F-13–F-14. Минимальный учёт нужен до платного исполнения, а не
после подключения всех генераторов. Мобильные/георасширения X-01–X-07 следуют
за web-профилем. Независимая работа возможна по схемам и fixtures; их нельзя
подставлять в основной runtime вместо отсутствующей реализации.

## Критерии хакатона

Максимум — 100 баллов; PDF не задаёт проходного порога, весов подпунктов или
формулы частичного начисления. Команда не придумывает эти правила.

| Категория | Баллы | Свидетельство для демонстрации |
|---|---:|---|
| Анализ | 20 | Исходный запрос, FR/NFR, доказательные цитаты, вопросы/допущения, критерии приёмки |
| Продукт и интерфейс | 15 | Предметный web/mobile сценарий, UI Kit, состояния и реальные API |
| Архитектура и разработка | 20 | Контракты API/data/UI, модель, миграции, код и трассировка |
| Тестирование и безопасность | 15 | Фактически выполненные проверки, дефекты и отчёты |
| Инфраструктура | 10 | Docker, воспроизводимость, GitLab CI/CD, build/deploy и артефакты |
| Документация | 10 | Согласованные описание, OpenAPI, инструкции и руководства |
| Эффективность | 10 | Время, отдельные input/output tokens, вызовы, попытки и ручные уточнения |

Оценивается универсальный pipeline или значимый участок на двух кейсах: известном
и скрытом, который запускают во время оценки. Предметный вход — только требования,
не большая обязательная анкета. Известный кейс — платные парковки Санкт-Петербурга:
маршрут/въезд в зону → уведомление → подтверждение сессии → предупреждение за
10 минут → выход/смена зоны → история в административном UI. Нужны границы/номер
зоны, параметры, статус/остаток времени, маршрут/история и переход в официальный
сервис оплаты. Реальная оплата/промышленный внешний доступ не требуются.
Web-админка не заменяет мобильный помощник.

Полный конкурсный контур включает проверки, безопасность, контейнеризацию,
сборку и deploy; генерация этих этапов исключена из текущего объёма команды.
Это оставляет непокрытыми категории на 25 баллов, но не гарантирует остальные 75.
Для разработки и итоговой демонстрации применяются разные ключи модели;
неизвестный usage обозначается явно, не нулём. Измеряются generation active time
и elapsed с паузами раздельно; успех генерации не выводит PASS build/test/deploy.

Материалы показа: исходный запрос/ответы, снимок с SHA, анализ/архитектура/API/data,
руководство, FR→files, метрики и честные ограничения. Сохранённый заранее пример
не заменяет генерацию на выданных требованиях.

## Разработка

Задачи и обсуждения: [GitHub Issues](https://github.com/Krastti/RWB-Hack/issues).
Правила веток, review, восстановления `main` и выпуска — в
[CONTRIBUTING.md](CONTRIBUTING.md). Изменение контракта согласуется с потребителями;
локальные тесты и закрытая Issue не заменяют независимое review.

### Docker Compose

Скопируйте `.env.example` в `.env`, заполните LLM-параметры,
`POSTGRES_PASSWORD` и `JWT_SECRET_KEY` (минимум 32 байта).
Запуск API, worker, PostgreSQL, Redis и миграций:

```sh
docker compose up --build -d
docker compose logs -f api worker
```

API: http://localhost:8000. Данные PostgreSQL сохраняются в named volume.
Для архитектурного этапа требуется server-approved `PIPELINE_POLICY_FILE`: путь
внутри образа или файла, подключённого через volume. Пользователь для входа
создаётся по инструкции backend. Настройки `.env` передаются API и worker;
адреса PostgreSQL и Redis внутри Compose устанавливаются автоматически.

Frontend также запускается через Compose: http://localhost:4200
(порт задаётся `FRONTEND_PORT` в общем `.env`). Angular собирается в Docker,
Nginx обслуживает SPA и проксирует `/api/` на сервис API.
Ключ LLM остаётся в окружении backend/worker и не передаётся frontend.

При первом запуске Compose создаёт пользователя панели из `PANEL_LOGIN` и
`PANEL_PASSWORD` в `.env`. Существующий пользователь с таким логином не
изменяется: смена этих переменных не сбрасывает его пароль.

Для проверенного провайдера Qwen/vLLM в `.env` используются
`LLM_RESPONSE_FORMAT=json_schema_compat`, `LLM_ENABLE_THINKING=false`,
`LLM_MAX_OUTPUT_TOKENS=8000`, `LLM_TIMEOUT_SECONDS=120`. Режим compat передаёт
провайдеру поддерживаемую структурную схему; полный исходный JSON Schema и
предметные проверки остаются обязательными в backend. Явные HTTP отказы без
usage освобождают резерв токенов; подтверждённый usage сохраняется, таймауты
и ошибки сервера с неизвестным usage сохраняют резерв.

Серверные политики архитектуры подключаются через каталог `config`: см.
[инструкцию](config/README.md). Пример предназначен для предметной области
ремонтных заявок. Принятые результаты доступны до assembly через
`GET /api/v1/runs/{run_id}/accepted-artifacts` (C-01 2.3.0); существующие
manifest/ZIP DTO сохранены.
