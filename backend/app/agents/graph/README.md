# A-04: граф анализа и уточнений

Контракты: [C-02](../../../../contracts/agents/README.md),
[C-03](../../../../contracts/lifecycle.md), schema_version `1.0`;
база main — `ef1956c958ef64c8784ce0558c53269bea25142f`.

Граф: `begin_attempt → analyse → await_answers → prepare_resume → begin_attempt`.
После успеха или ошибки анализ останавливается. Успех анализа оставляет Run в
`running`: готовность всего проекта определяет общий оркестратор, не этот модуль.
`stage_id` задаётся доверенной конфигурацией (по умолчанию `analysis`), не моделью.

## Интерфейс

- `AnalysisGraph(node, artifacts, checkpointer, stage_id="analysis")` принимает
  аналитический узел, хранилище и LangGraph checkpointer через интерфейсы
  [state.py](state.py). Нужен адаптер аналитика A-03 к C-02; старый аналитик 0.1
  автоматически не подключается.
- `start(request, attempt_id=...)` принимает C-02 AgentInput и UUID уже
  зарегистрированной первой попытки (`attempt=1`). Повтор той же команды восстанавливает Run;
  другой исходный запрос с тем же run_id отклоняется.
- `snapshot(run_id)` читает состояние; `recover(run_id)` продолжает незавершённые
  узлы из checkpoint. Ожидание и завершённый анализ не вызывают модель повторно.
  Восстановление учитывает сохранённые записи задач даже при пустом `next`:
  сбой checkpoint после принятия ответов не оставляет граф в прежнем ожидании.
- `resume(run_id, questions_revision=..., answers=[{question_id, value}],
  attempt_id=...)` принимает UUID следующей зарегистрированной попытки и полный
  пакет оставшихся обязательных ответов. Проверки выполняются до изменения
  checkpoint. Повтор идентичной последней команды не создаёт ещё одну попытку.

Пример вызова из синхронного worker (аргументы предоставляет B-13):

```python
from backend.app.agents.graph import AnalysisGraph, open_checkpoints


def analyse(node, artifacts, request, attempt_id, checkpoint_path):
    with open_checkpoints(checkpoint_path) as saver:
        graph = AnalysisGraph(node, artifacts, saver)
        return graph.start(request, attempt_id=attempt_id)


def answer(node, artifacts, run_id, revision, answers, attempt_id, checkpoint_path):
    with open_checkpoints(checkpoint_path) as saver:
        graph = AnalysisGraph(node, artifacts, saver)
        return graph.resume(run_id, questions_revision=revision,
                            answers=answers, attempt_id=attempt_id)
```

`checkpoint_path` — абсолютный путь в существующем каталоге данных за пределами
репозитория, например `/var/lib/rwb/analysis.sqlite`. Ожидание не удерживает
соединение или worker: можно закрыть saver и открыть его заново при ответе.
SQLite — локальный сохраняемый adapter для одного worker; для распределённого
исполнения передаётся совместимый saver с общим устойчивым хранилищем.
Сериализатор не разрешает pickle и произвольные типы из checkpoint.

## Сохранение и восстановление

`durability="sync"` сохраняет границу узла до запуска следующего. В checkpoint
находятся run/stage/attempt, версия контрактов, профиль, hash входа, вопросы с
подтверждёнными ответами, references артефактов, история попыток с временами,
usage и диагностикой. Содержимое файлов и ответы провайдера туда не копируются.

Аналитик и `interrupt` находятся в разных узлах: повтор входа в ожидающий узел
не вызывает LLM. Ответ создаёт новый неизменяемый analysis-input с прежним
бизнес-текстом, ссылкой на предыдущие требования и накопленными ответами.
Номер попытки увеличивается; успешные результаты остаются в истории.
Первый опубликованный снимок вопросов имеет questions_revision=1, в том числе
при пустом questions: отсутствие уточнений не блокирует успешный анализ.
Вопросы и подтверждённые ответы не переименовываются; у отвеченного вопроса
нельзя менять текст, причину, required или набор связанных FR под тем же UUID.
Новый уточняющий вопрос получает новый UUID, прежний ответ остаётся связан
с прежним определением. Изменение только answer или порядка FR IDs не повышает
questions_revision. Проверяются сохранность прежних ID требований FR/NFR и ролей, evidence,
checksum, соответствие вопросов в артефактах и отсутствие выдуманных ответов.
При уточнении разрешено добавлять новые FR/NFR и роли, сохраняя прежние ID.

ArtifactStore должен проверять владение, сохранять неизменяемые артефакты и
атомарный receipt принятого AgentResult. После сбоя между записью receipt и
checkpoint граф использует receipt, не вызывает модель повторно. Если процесс
оборвался после внешнего LLM-запроса, но до receipt, повтор запроса возможен:
exactly-once для внешней модели не гарантируется; adapter учитывает такой расход.
При отклонении результата валидный usage текущей попытки сохраняется отдельно;
неизвестный usage остаётся `None`, не превращается в нулевой расход.

Невалидный результат останавливает анализ с безопасным кодом `GraphError` в
истории, не применяется как успех. Ошибки хранилища/checkpointer могут выйти
исключением: bridge должен сохранить причину и восстановить ту же команду после
устранения сбоя. Нет checkpoint — `RESUME_STATE_UNAVAILABLE`; восстановление из
канонических данных Run остаётся обязанностью серверного восстановителя B-13.

## Границы подключения

Это внутренний граф, не HTTP API или транзакционный сервис Run. B-06/B-08/B-12/
B-13 обеспечивают авторизацию, lease/fencing, idempotency records, атомарное
принятие ответов и pending-попытки в БД, outbox и запись публичных событий.
Параллельные вызовы одного run_id без внешнего lease запрещены.
Счётчики/резервы бюджета и автоматический repair относятся к A-20/B-19;
граф не запускает автоматические повторы и не сбрасывает принятую историю.
Ответы `cancelled`/`skipped` от аналитика без управляющего решения не объявляют
успех Run: обязательный анализ останавливается с `failed`.

Установка из корня репозитория в выбранное окружение:

```sh
python -m pip install -r backend/app/agents/graph/requirements.txt
python -m unittest discover -s backend/app/agents/graph -p 'test_*.py' -v
```

Проверки используют существующие C-02 fixtures и временные SQLite-файлы:
ожидание/возобновление, повтор доставки, ревизии, невалидные ответы/результаты и
сбой записи checkpoint после принятия результата. Они не обращаются к LLM.
Поведение interrupt/checkpointer следует [документации LangGraph](https://docs.langchain.com/oss/python/langgraph/interrupts).

Реальные LLM, HTTP, очередь, PostgreSQL и переход к архитектуре здесь не
подключены. Их готовность не следует из успешного локального вызова графа.
